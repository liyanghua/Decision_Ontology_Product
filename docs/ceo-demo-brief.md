# CEO 级极简口径（经营搭档 Demo）

一页纸供产品 / 高管场内部对齐，与完整演练脚本见 [demo-storyline.md](./demo-storyline.md)。

## 核心判断

卖的不是「更多页面」，而是 **一条可重复的决策闭环**：盘面重点 → 单点诊断与打法 → 放行与推进 → 看结果 → 沉淀为经验。高管通常只关心三件事：**省时间、控风险、可复盘**。

## 演示边界（一句话口径）

事先约定：本 Demo 中，哪些属于 **产品逻辑与数据结构的假设验证**，哪些属于 **会议用快照 / 本地演示数据**。与生产 ERP、BI、广告后台的对接关系放在 **Q&A**，主讲述不展开技术集成细节。

## 五条建议

1. **讲清一层边界**  
   避免被追问「这和生产系统是什么关系」时被动；主讲述聚焦闭环与操盘手价值。

2. **押注一条主故事线**  
   全员按同一脚本走（与 [demo-storyline.md](./demo-storyline.md) 对齐）。宁可少讲模块，也不切换叙事。

3. **语言统一成「操盘手词典」**  
   全链路优先使用：今日重点、关键风险、优先处理、推荐打法、去推进、看结果、形成经验。字段、链路、CSV 等留给研发 Q&A，不进入主讲述。

4. **会前只防两处翻车**  
   - **空队列**：会前加载好队列数据；若为空，用约 10 秒说明需先到商品操盘台加载（见 demo-storyline 环境前提）。  
   - **本地经营记忆**：首页「经营记忆」来自浏览器本地偏好，**不是**公司主数据；一句话交代即可。

5. **扩功能前的反转问题**  
   新模块是否让 **闭环更可信**，还是只增加 **认知负担**？若不能缩短「发现 → 沉淀经验」的路径，暂缓。

## 演示环境说明（极简）

- 建议本地已加载商品队列（`liveCatalog` 非空），故事线最顺。  
- 详细步骤与路由表见 [demo-storyline.md](./demo-storyline.md)。

## 原则

**一条故事、一套用词、一层边界、两处会前检查。**
